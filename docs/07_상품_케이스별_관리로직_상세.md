# 07. 상품 케이스별 등록·가격·재고 관리 로직 상세

> 하나의 공급사가 다양한 관리 포인트(시간대별·구성별·재고 유무별·구성별 가격)의 상품을 자유롭게 구성할 수 있어야 한다.
> 본 문서는 **실제 OTA에서 판매 중인 상품 사례(웹 리서치로 확인)** 를 카테고리별로 전부 나열하고, 각 케이스의 ① 상품 등록 방법(순서) ② 가격 관리 로직 ③ 재고 관리 로직을 절차 텍스트로 명시한다.
> 도메인 모델 용어는 [03_도메인_모델_설계.md](03_도메인_모델_설계.md) 기준 (Product / Option / Unit / PriceRule / AvailabilitySlot).

## 2. 티켓(입장권/패스) 케이스

### T1. 시간대별 입장권 — 에버랜드 종일권/오후권/야간권형

**실제 사례**: 에버랜드 종일권(10:00~) / 오후권(14:30~ 또는 15:00~) / 야간권(17:30~). 시즌 A/B/C/D별 가격 상이(종일권 대인 46,000~68,000원), Klook은 화·수·목 평일 특가 별도 운영. 재고는 무제한.

**상품 등록 방법 (순서)**
1. Product 생성: 카테고리 C1(입장권), 가용성 유형 = `OPENING_HOURS`(일자 지정·시간 미지정), 확정 방식 = 즉시확정, 바우처 = QR(예약당 1장 또는 인원당 — 게이트 정책에 따름)
2. Option을 **시간대별로 분리 생성**: "종일권", "오후권", "야간권" — 각 Option에 입장 가능 시작시각을 속성으로 기재(콘텐츠·바우처 표기용). ※ 시간대는 재고 슬롯이 아니라 **Option 분리**로 표현하는 것이 핵심 (재고가 시간대별로 분리되지 않고 가격만 다르기 때문)
3. 각 Option에 Unit 등록: 대인 / 청소년 / 소인(36개월~만12세) / 경로(만65세+). 36개월 미만 무료는 `FREE_NO_TICKET`(티켓 불요, 현장 증빙) 유닛으로 등록
4. 취소정책 연결(예: 이용일 전일까지 전액 환불)
5. 운영 스케줄 등록: 기간 = 판매기간 전체, 요일 = 매일, 세션 시각 없음, **정원 = 무제한(null)** → 일자별 슬롯 자동 생성(capacity 없음, 블록아웃용)
6. 가격 등록 (아래 로직)
7. 검수 후 게시, 채널 매핑(Option별로 채널 상품ID 연결)

**가격 관리 로직 (순서)**
1. **시즌 캘린더 정의**: 공급자가 날짜 구간별 시즌 등급(A/B/C/D)을 캘린더에 지정 (예: 12/24~12/31 = A)
2. Option × Unit 별로 **시즌별 PriceRule 등록**: (종일권, 대인, 시즌C) = 46,000 / (종일권, 대인, 시즌A) = 62,000 / (오후권, 대인, 시즌C) = 40,000 … — 시간대 차등은 Option이 분리되어 있으므로 Option별 룰로 자연 표현됨
3. 채널 특가가 있으면 채널+요일 조건 룰 추가: (종일권, 대인, 채널=Klook, 요일=화·수·목) = 39,000
4. **가격 결정(판매 시)**: 이용일 → 해당 일자에 매칭되는 룰 중 우선순위 최상 룰 선택 (특정일 > 채널+요일 > 시즌 > 기본가) → Unit별 단가 × 수량 합산
5. 예약 생성 시 적용 룰과 금액을 **스냅샷 저장** (이후 가격 변경과 무관하게 보존)

**재고 관리 로직 (순서)**
1. 슬롯 capacity = null(무제한) → 잔여 검증 없이 항상 판매 가능
2. 단, 슬롯 상태는 유지: 공급자가 특정일 판매 중지 시 해당 일자 슬롯 `CLOSED`(블록아웃) → 전 채널 판매 차단 + 매진 통보
3. 판매량 집계는 `booked_count`로 계속 기록 (정산·통계용, 차감 검증만 생략)
4. 시설이 입장 상한을 도입하면 capacity 값만 입력하면 한정 재고로 전환됨 (모델 변경 없음)

### T2. 날짜미지정(오픈데이트) 입장권 — 에버랜드 날짜미지정 종일권형

**실제 사례**: 마이리얼트립 등에서 "날짜미지정 종일권, 유효기간 ~2026/03/31" 형태로 병행 판매. Klook FAQ 기준 오픈데이트 = 구매일로부터 90일/3개월 등 유효기간 내 아무 날짜 사용, blackout date 제한 가능.

**상품 등록 방법 (순서)**
1. Product 생성: 가용성 유형 = `FREESALE`(재고 검증 불요), **유효기간 규칙 입력**: 기준 = 구매일(PURCHASE) / 기간 = 90일 — 또는 절대 만료일(~2026/03/31)
2. Option 생성: "날짜미지정 종일권" (T1과 별도 Option 또는 별도 Product — 지정일권과 병행 판매 시 별도 Option 권장)
3. **blackout date 등록**: 사용 불가 일자(특정 공휴일 등) 목록 — 바우처 사용 조건으로 저장
4. Unit·취소정책·가격 등록 후 게시

**가격 관리 로직 (순서)**
1. 날짜 축이 없으므로 **고정 단가 1개** (Unit별). 시즌 룰 불필요
2. 관행상 지정일권 최고 시즌가와 유사하거나 높게 책정 (아무 날짜나 쓸 수 있는 유연성 프리미엄) — 가격 정책 가이드로 안내
3. 유효기간 연장 유료 옵션을 둘 경우 연장 수수료를 별도 상품(부가 서비스)으로 등록

**재고 관리 로직 (순서)**
1. **판매 시 재고 차감 없음** (무제한). 슬롯 생성도 불필요
2. 바우처 수명주기로 관리: `발급 → (유효기간 내) 사용가능 → 리딤 → 만료` — 만료 배치가 유효기간 경과 미사용 바우처를 EXPIRED 처리
3. 리딤 시점 검증: ① 유효기간 내인가 ② 당일이 blackout date가 아닌가 ③ 미사용 상태인가 — 3단 검증 통과 시 사용 처리
4. 총량 한정 판매(수량 한정 프로모션)가 필요하면 가상 슬롯 1개에 capacity 설정으로 전환

### T3. 날짜별 tier 가격 입장권 — 도쿄디즈니/USJ/상하이디즈니형

**실제 사례**: 도쿄디즈니 1-Day ¥7,900~12,400 (일자별 tier, 약 60일 전 캘린더 공개), USJ A~F 6단계 시즌 등급 ¥8,600~10,900, 상하이디즈니 Regular 475 → Peak++ 799 CNY (30일 rolling 판매).

**상품 등록 방법 (순서)**
1. Product 생성: `OPENING_HOURS`, 지정일 필수
2. Option 생성: 1-Day / 2-Day / 1.5-Day(첫날 15시 입장) / 파크 선택 등 — 권종별 Option 분리
3. Unit 등록 (성인 / 아동 4–11세 등 — **연령 경계는 시설 정의를 그대로 입력**)
4. **가격 tier 체계 정의**: tier 명칭과 tier별 가격표 등록 (예: Tier1 ¥7,900 … Tier6 ¥12,400)
5. **일자→tier 배정 캘린더 입력**: 월 캘린더 화면에서 일자별 tier를 지정 (대량 입력: 기간+요일 조건 일괄 배정 → 예외일 개별 수정)
6. 판매 오픈 윈도 설정: rolling 판매(이용일 D-30/D-60부터 판매 오픈) 규칙
7. 게시 및 채널 매핑

**가격 관리 로직 (순서)**
1. 가격은 2단 분리: **① tier별 가격표** (tier×Option×Unit 단가) + **② 일자별 tier 배정** — 가격 개정 시 ①만 수정하면 전 일자 반영, 특정일 성수기 전환 시 ②만 수정
2. 판매 시 가격 결정: 이용일 → 배정 tier 조회 → tier 가격표에서 Option×Unit 단가 확인 → 합산
3. tier 미배정 일자는 판매 불가(가격 미정) — 배정 캘린더 공개 주기(60일 전)와 판매 오픈을 연동
4. 2-Day 증분가 방식(1-Day + 정액) 지원: 2-Day Option 가격을 "참조 Option + 증분" 수식으로 정의 가능하면 개정 작업 최소화 (선택 구현)
5. 채널에는 **일자별 가격 캘린더 API**(availability calendar + pricing)로 노출 — 대량 조회 최적화 필수

**재고 관리 로직 (순서)**
1. 기본 무제한 + 일자별 매진 전환 가능: capacity = null로 운영하다 시설이 입장 상한 통보 시 해당 일자 슬롯에 capacity 입력 또는 `CLOSED` 처리
2. 매진/재개 시 전 채널 즉시 통보 (매진 오인·초과 판매 방지)
3. 판매 오픈 윈도 밖(D-60 이전) 일자는 슬롯 상태와 무관하게 판매 차단

## 8. 패키지/번들 케이스

### B1. 혼합 재고 번들 — 에버랜드 티켓+셔틀+밀쿠폰형

**실제 사례**: Klook 에버랜드 왕복셔틀 콤보, 3-in-1(티켓+셔틀+밀쿠폰) — 노선(강북/강남)·승차지 선택, 티켓(무제한)+셔틀(좌석 한정, 주말 조기 매진, 최소 2일 전 예약)+밀쿠폰(무제한) — **재고 모델이 다른 컴포넌트의 결합**. 홍콩디즈니 티켓+밀쿠폰(Lunch OR Dinner vs Lunch AND Dinner 구성별 SKU). Trazy 티켓+Q-Pass+셔틀.

**상품 등록 방법 (순서)**
1. **컴포넌트 상품을 먼저 각각 등록**: 에버랜드 티켓(T1 방식), 셔틀버스(A1 방식 — 노선별 Option·차량 좌석 capacity), 밀쿠폰(F1 방식) — 각자 단품 판매 여부는 독립 설정
2. 번들 Product 생성: C8, **정적 번들** — ProductComponent로 [티켓 Option, 셔틀 Option, 밀쿠폰 Option] 연결
3. **선택 축 정의**: 고객이 고르는 축만 노출 — 셔틀 노선/승차지(컴포넌트 Option 선택), 시간대권 종류. 나머지는 고정
4. 번들 Unit(성인/아동 — 컴포넌트 Unit과 매핑 정의: 번들 성인 = 티켓 대인 + 셔틀 성인 + 밀쿠폰 성인)
5. 번들 가격 등록 (아래), 취소정책(전체 취소 기본 / 부분 취소 허용 여부) 설정
6. **바우처 규칙**: 컴포넌트별 개별 바우처 발급(티켓 QR + 셔틀 탑승권 + 밀쿠폰) — "셔틀 콤보는 직접 입장 QR 불가" 같은 컴포넌트별 사용 방식 차이를 명기
7. 게시

**가격 관리 로직 (순서)**
1. 번들가 = 정액 직접 입력 (권장) — 컴포넌트 합산가와 독립. 등록 화면에 "컴포넌트 합산가 대비 할인율" 자동 표시로 검증 보조
2. 컴포넌트 가격 변동 시(티켓 시즌가) 번들가 처리 2방식: ① 번들 정액 유지(마진 변동 감수) ② **합산−할인 산식**(번들가 = Σ컴포넌트가 × 0.9) — 상품별 선택
3. 정산·매출 배분: 번들 매출을 컴포넌트별 배분 규칙(배분율 또는 넷가 기준)으로 분해 — 리포트·정산 라인 생성용

**재고 관리 로직 (순서) — 번들의 핵심**
1. **가용성 = min(각 컴포넌트 가용성)**: 조회 시 티켓(무제한=∞), 셔틀 해당 노선·일자 잔여(예: 3석), 밀쿠폰(∞) → 번들 잔여 = 3
2. 예약 생성 시 **전 컴포넌트 재고를 단일 트랜잭션으로 차감**: 티켓(차감 생략—무제한) + 셔틀 슬롯 3석 중 2석 차감 + 밀쿠폰(생략) — 하나라도 실패하면 전체 롤백(NO_AVAILABILITY)
3. 컷오프 = **max(컴포넌트 컷오프)**: 셔틀이 2일 전 마감이면 번들도 2일 전 마감
4. 취소 시 전 컴포넌트 재고 동시 복원. 부분 취소 허용 상품은 컴포넌트 단위 취소(셔틀만 취소 → 차액 환불)
5. 컴포넌트 중 하나가 매진/판매중지 되면 **번들 자동 판매중지** + 공급자 알림

### B2. 호텔+티켓 패키지 — RWS 호텔+USS형

**실제 사례**: RWS Hotel Michael 2박+USS 티켓 — [호텔 선택] × [박수] × [룸타입] + 고정 포함물(조식 2인, USS 티켓 2매, 기프트 바우처). **객실 요금은 체크인 날짜별 변동**(숙박형 dynamic pricing) + 티켓 정액 결합. 재고는 객실 allotment가 지배, 취소 규정은 호텔 룰.

**등록 순서 (순서)**
1. 객실 컴포넌트 등록: 룸타입별 Option, **일자별 객실 allotment**(방 수) + 일자별 객실 요금 (T3 tier 방식 또는 일자별 직접 입력)
2. 티켓 컴포넌트: 기존 티켓 상품 참조
3. 번들 Product 생성: [룸타입 Option × 박수] 조합 + 고정 포함물 목록. **체크인일 = 기준일**, 연박은 연속 일자 검증
4. 취소정책 = 호텔 룰 기준(체크인 N일 전) — 티켓 정책보다 우선함을 명시
5. 가격·게시

**가격 로직**: 패키지가 = Σ(체크인~체크아웃 각 일자 객실가) + 포함물 정액 − 패키지 할인. 일자별 객실가 변동이 그대로 반영되는 **동적 합산** 구조.
**재고 로직**: **연박 기간 점유형**(E2와 동일 원리) — 체크인~체크아웃 전 일자의 객실 allotment를 동시 차감, 하나라도 부족하면 거부. 티켓은 종속 발권(투숙 확정 시 자동 발급).

## 9. 횡단 케이스 — 프로모션·가격 규칙 (X1)

**실제 사례**: GYG early bird(N일 전 예약 시 X% 할인 + 할인 좌석 수 제한), GYG 그룹 계단가(8인 이상 인당 인하), Klook 평일(화·수·목) 특가, 외국인 전용 상품, last minute 할인.

**등록 방법 (순서)**
1. 프로모션 유형 선택: early bird / last minute / 기간 한정 / 채널 전용 / 요일 한정
2. 대상 지정: Product/Option/Unit 범위
3. 조건 입력: 예약 시점 조건(이용일 D−N일 이전/이내), 이용일 조건(기간·요일), 채널 조건
4. 할인 방식: 정률(%) 또는 정액, **할인 적용 한도**(세션당 할인 좌석 수 — GYG seat limitation)
5. 유효기간·중복 적용 규칙(프로모션 간 중복 불가 기본) 설정 후 활성화

**가격 결정 공통 알고리즘 (전 케이스 최종 정리 — 판매 시점 실행 순서)**
1. 입력: Option, Unit×수량, 이용일(+슬롯 시각), 채널, 예약 시점
2. 기본 단가 결정: 해당 조건에 매칭되는 PriceRule 수집 → 우선순위 정렬(**특정일 > 시간대(time band) > 채널+요일 > 요일 > 시즌 > 기본**) → 최상위 룰 채택
3. 인원 구간(tiered) 룰이 있으면 총 인원으로 구간 판정 후 단가 치환
4. 프로모션 적용: 조건 충족 + 할인 한도 잔여 확인 → 할인 적용 (한도 카운트 차감)
5. Add-on 합산 → 총 판매가 확정 → **가격 스냅샷 저장**(적용 룰 ID·단가·할인 내역)
6. 채널 판매 시 넷가 = 판매가 − 채널 커미션 (또는 채널별 넷가 룰 직접 적용) — 정산 기준 동시 스냅샷

**재고 차감 공통 알고리즘 (전 케이스 최종 정리)**
1. 재고 모드 판정: 무제한(FREESALE) → 차감 생략, 카운트만 / 슬롯형 → 2번 / 기간 점유형 → 대상 일자 전개 후 2번을 전 일자에
2. 원자적 조건부 차감: `잔여(capacity − booked − held) ≥ 요청 수량`일 때만 held 증가 — 실패 시 NO_AVAILABILITY
3. 번들이면 전 컴포넌트를 단일 트랜잭션으로(하나라도 실패 시 전체 롤백)
4. 확정 시 held → booked 전환, 홀드 만료·취소 시 복원
5. 잔여 0 도달/해제 시 채널 매진/재개 통보 이벤트 발행
