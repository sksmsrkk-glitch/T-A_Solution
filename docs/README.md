## 핵심 설계 결정 요약

1. **상품 구조**: 업계 표준 **Product → Option(패키지) → Unit(판매 단위)** 3계층 (OCTO/Klook/GYG/KKday 공통 패턴)
2. **재고 3유형 단일 추상화**: 타임슬롯(START_TIME) / 일자(OPENING_HOURS) / 오픈데이트(FREESALE + 유효기간)
3. **가격 3층 × 룰 기반**: 정가/판매가/공급가 × (Unit·시즌·채널·인원구간) 룰, 예약 시점 스냅샷 보존
4. **예약 = 2단계 커밋 상태머신**: ON_HOLD → CONFIRMED(즉시) 또는 PENDING(온리퀘스트) → REDEEMED/CANCELLED/NO_SHOW
5. **오버부킹 방지**: DB 조건부 갱신(원자적 차감) + 멱등키 + 홀드 만료 배치
6. **채널 연동 2모델**: PULL(OCTO API 서버 — Klook/GYG) + PUSH(어댑터 — KKday/Trip.com), 이벤트 기반 동기화
7. **아키텍처**: 모듈러 모놀리스 + 채널 게이트웨이 분리, PostgreSQL 단일 진실 원천
